# SemiRisk 项目自审报告

## 1. 自审结论

当前项目可本地运行，前端 Vue、后端 Maven 多模块、公开源爬虫、Token 认证权限、报告导出、预警处理、GIS 多线路和知识库 ES 检索链路已经打通。风险类页面已从固定演示数据改为公开 RSS 采集数据驱动；公开源不可达时显示待采集或采集失败。

## 2. 前端审查

- 结构：`src/api`、`src/composables`、`src/views`、`src/layout` 已拆分，页面不再集中在单文件逻辑中。
- 登录权限：未登录仅开放首页，登录/注册入口保留在侧栏账户区，顶部只显示未登录提示；登录失败会展示后端错误提示。
- 注册：前端校验 QQ 邮箱，后端二次校验；启动管理员为 `kaduoxli / 123qwe123`，公开注册账号默认为 `OPERATOR`。
- Token：前端保存 Bearer Token 和 `expiresAt`，30 分钟滑动有效；刷新当前路由会恢复并重载当前页面数据，过期刷新会回首页重新登录。
- GIS：已改为后端 `points` + `routes` 数据驱动，并提供 3D 立体视图、自动旋转、手动拖拽和点位弹窗，避免固定一条或少量假线路。
- 预警中心：已补状态筛选、复选框批量处理、公开源链接、已忽略过滤；点击详情仅展示当前告警，并提供中英文对照。
- 知识库：页面只保留 AI 智能体问答面板，展示答案、检索链路、引用、模型状态和 token 使用量。
- 固定分页：Dashboard、风险详情、企业画像和系统日志已改为固定长度分页面板，减少长页面纵向堆叠。
- UI 微调：保留深色蓝紫赛博色调，收敛侧栏、Topbar、KPI、固定面板、3D GIS、分页按钮和表格密度，移除顶部重复退出按钮，退出/切换账户集中在左下角。

## 3. 后端审查

- 认证：登录注册优先持久化 MySQL `system_user`，密码 PBKDF2 哈希；登录失败计数优先走 Redis Cluster，集群不可用时内存兜底。
- 权限：Gateway 拦截器已按 URI 映射模块并执行后端 RBAC 校验，避免只依赖前端菜单隐藏。
- 安全：受保护接口使用 `Authorization: Bearer <token>`；写接口启用无 Cookie 签名 CSRF Token；响应头已加 CSP、nosniff、frame deny、referrer-policy 和 permissions-policy。
- 爬虫：`semirisk-data-service` 使用公开 RSS/Atom 源并返回原文 URL、维度、评分、采集状态；服务启动和手动刷新会实时爬取，数据、风险和 AI 自动刷新周期已统一为每 12 小时。
- Gateway：聚合公开源数据到 Dashboard、Alert、GIS、Knowledge、Risk Analysis。
- 告警：公开源告警状态写入 Gateway 状态集，忽略和批处理后可正确反映到默认列表和计数器。
- 报告：`ReportFileFactory` 统一生成 PDF、DOCX、PPTX，Gateway 和 report-service 复用。
- 知识库：Gateway 会把公开源成功记录写入 Elasticsearch `semirisk_knowledge`，搜索和问答优先走 ES，ES 不可用时回退本地公开源记录。
- AI 问答：`/api/knowledge/ask` 已结合本地知识库、公开源、ES 检索和 DeepSeek Chat Completions；返回 `aiCalled`、`modelStatus` 和 `usage.totalTokens` 用于确认真实调用。
- 启动账号：`BootstrapAdminProvisioner` 会在 Gateway 启动时初始化 `kaduoxli` 管理员，VM/MySQL 不可达时使用内存兜底，MySQL 可达时同步落库。
- 性能：公开源同步增加短超时，ES 写入取消逐条 `refresh=wait_for`，并在 Gateway 入口做 120 秒节流，避免告警、GIS、知识库页面被同步任务阻塞。

## 7. 本轮真实化改造（全部真实数据 + 全部入库）

- **零虚假数据**：删除写死的演示数据集——企业种子画像（含虚构法人/注册资本/信用代码）、AI 报告静态文本、上传假日志与随机行数、系统监控假 Agent/假数据源/假延迟、GIS 固定坐标轮转。页面上每个值要么来自真实来源（公开源爬虫 / 中间件 / 模型 / 用户输入），要么明确标注「待采集 / 待接入权威源」。
- **全部入库 MySQL**：新增 `auth_token`、`crawler_signal`、`risk_snapshot`、`knowledge_doc`、`enterprise_record`、`ai_report` 表；Token、公开源信号、风险快照、告警状态、企业画像、知识库文档、AI 报告统一以 MySQL 为事实源，重启可恢复，内存仅作降级兜底。
- **Token（原剩余风险）**：迁移到 MySQL `auth_token`，30 分钟滑动续期、重启与多实例共享生效。
- **告警状态（原剩余风险）**：公开源告警状态写入 `risk_alert` 并在启动时回填，重启后保留处置结果。
- **AI 报告**：网关聚合公开源 + 风险快照真实调用 DeepSeek 生成本日报告并入 `ai_report`，接入 Dashboard；`ai-service` 同步改为拉取 data-service + 调用 DeepSeek 的真实实现。
- **上传管线**：文件真实落 MinIO，`parse` 用 Apache POI / CSV 解析真实行数与字段告警，SSE 日志反映真实处理步骤。
- **知识库预览**：`/api/knowledge/preview/{id}` 从 MinIO 拉取真实对象或返回知识库真实正文。
- **系统运维**：模型连通性测试、数据源重连、Agent 触发改为对真实 endpoint / 中间件 / 任务的真实探测与执行。
- **知识库分类**：「内部知识库 / 政策法规库」不再「待接入」——内部 SOP 入 `knowledge_doc`，政策法规由新增公开源（联邦公报出口管制/半导体、WTO）实时爬取入库，分类计数真实。
- **企业工商**：改为公开主体观察名单 + 实时公开源事件聚合入库；工商权威字段统一「待接入权威源」，不伪造。
- **GIS**：删除固定坐标，改为真实地名→真实经纬度地理编码。

## 8. 代码质量优化

### 8.1 Gateway 服务层按领域拆分

原 `SemiRiskStore.java` 为 2396 行单体服务类，已按领域职责拆分为 11 个独立服务和 10 个数据模型，收拢至 `com.semirisk.model` 包：

| 拆分前 | 拆分后 | 行数 | 职责 |
|---|---|---|---|
| 用户认证相关 | `AuthService.java` | ~226 | 认证、Token、防爆锁、重置 |
| 告警相关方法 | `AlertService.java` | ~155 | 告警查询、状态流转、公开源告警派生 |
| 上传相关方法 | `UploadService.java` | ~157 | 上传任务、文件解析、SSE 推送 |
| 报告相关方法 | `ReportService.java` | ~536 | 报告调度、AI 报告生成、异步执行 |
| Dashboard 相关方法 | `DashboardService.java` | ~364 | KPI 聚合、时间窗口分析、信号详情 |
| 系统管理相关方法 | `SystemManagementService.java` | ~219 | 用户管理、模型配置、审计日志 |
| SemiRiskStore 翻译相关方法 | `TranslationService.java` | ~156 | 标题翻译、枚举映射 |
| SemiRiskStore GIS 相关方法 | `GisService.java` | ~171 | 地理编码、点位、路径 |
| SemiRiskStore 企业相关方法 | `EnterpriseService.java` | ~348 | 企业画像、Wikipedia、搜索 |
| SemiRiskStore AI 相关方法 | `AiChatService.java` | ~214 | DeepSeek 调用、答案解析 |
| 其余核心逻辑 | `SemiRiskStore.java` | ~1580 | 风险快照、信号持久化、定时任务、知识聚合 |
| 内部记录类 (10 个) | `com.semirisk.model.*` | — | UserAccount、LoginState、RiskAlert、CrawlerSignal 等 |

拆分原则：单一职责、构造器注入协作、子服务间无直接依赖。编译验证通过。

### 8.2 Nacos Logback 冲突修复

Nacos SDK 内置 logback appender 配置与项目日志冲突，通过 `nacos.logging.default.config.enabled=false` 禁用 Nacos 内置日志配置解决。

### 8.3 RabbitMQ 连接配置补充

添加 `spring.rabbitmq.host/port/username/password` 属性，确保 Spring AMQP 自动配置可正确连接 RabbitMQ。

### 8.4 基础设施组件自审

- **线程池隔离**：6 个 `ThreadPoolTaskExecutor` 通过 `@Bean` 命名注册，优雅关闭时间 30-120s 不等。拒绝策略按业务优先级选择：爬虫/AI/上传/告警用 CallerRuns（背压保护），查询用 DiscardOldest（保最新），报告用 Discard（非紧急可丢弃）。
- **Redis 缓存**：4 个命名缓存独立 TTL，最长 300s（企业画像），最短 30s（风险快照）。使用 GenericJackson2JsonRedisSerializer 序列化，Null 值禁止存储。
- **限流**：滑动窗口算法，Redis Sorted Set 实现。注册 60s/2 次，验证码 60s/1 次。Redis 故障时放行（warn 日志）。
- **幂等**：SET NX + 5min TTL，读 `Idempotency-Key` 请求头，重复返回 409。排除登录/注册/Dashboard/预览接口。Redis 故障时放行。
- **分布式锁**：Redisson RLock，tryLock 可配置等待/租约时间，中断安全（恢复 interrupt 标志）。
- **安全响应头**：CSP 严格模式（frame-ancestors none），camera/microphone/geolocation 全部禁止。

### 8.5 向量检索自审

- `VectorSearchService` 构造时自动初始化 ES `dense_vector` mapping（cosine 相似度，768 维）。
- RRF 融合：关键词 `multi_match`（`title^3, content^2`）与向量相似度，rank constants 均为 60.0。
- 优雅降级：Embedding 端点未配置 → 纯关键词搜索；embedding 请求失败 → 向量分置 null。
- 无异常抛出，HTTP 错误返回空列表。

### 8.6 ES 批量写入自审

- `ElasticSearchBulkWriter`：`ConcurrentLinkedQueue` 内存缓冲，100 条 / 5 秒自动刷写。
- `@PreDestroy` 确保关闭时 flush 剩余缓冲。
- 熔断：bulk 发送失败或 search 失败 → ES 禁用 60 秒，失败文档重新入队。
- 监控：`bufferSize`, `totalFlushed`, `totalFailed`, `esDisabled` 公开状态。

### 8.7 AI 结构化输出自审

- `AiStructuredOutputService` 使用 DeepSeek `response_format: { type: "json_schema", strict: true }`。
- Temperature = 0.1 确保输出稳定。
- 4 场景：报告生成、文件评估、本日风险分析、问答。
- 失败时返回 null（调用方自行处理降级）。

### 8.8 数据清理自审

- `DataCleanupService`：每周日 02:00 `cron = "0 0 2 ? * SUN"`。
- 保留 90 天，归档 `crawler_signal` 旧数据到新表。
- `volatile boolean running` 防止并发运行。
- DDL 在独立事务外执行，数据迁移在事务内原子完成。

### 8.9 工具类自审

- `SafeLogger`（common）：SLF4J Level-aware，compute/warn/error/info 均有 fallback，不静默吞掉异常。
- `SafeLogger`（gateway）：上下文标记日志，catch 块中 warn/error/debug 带标签。
- `CircularBuffer`：O(1) 旋转，正确实现 Iterator。
- `ReportUtils`：null-safe 字符串/数字/Instant 解析，JSON 读写容错。
- `MaskPasswordConverter`：大小写不敏感密码脱敏，应用于 Logback pattern。

## 9. 剩余风险

- 公开 RSS / 政策法规源不是专用商业数据源，覆盖度与时效性取决于源站；源不可达时显示采集失败，不伪造。
- 企业工商权威数据源（工商/司法/失信）仍未接入，企业画像不显示工商字段，统一「待接入权威源」，已预留适配层接入点。
- DeepSeek 调用依赖可用 API Key 与外网连通性；失败时回退本地聚合摘要并在 `modelStatus` 说明。
- GIS 坐标为按公开源涉及/来源地区映射的真实地理坐标，不等同实时物流 GPS。
- AI 模型路由已从 `deepseek-chat`（通用路由别名，可能分配到 flash 等廉价模型）改为 `deepseek-v4-pro`（精确指定），确保报告生成始终使用 v4-pro 模型。
