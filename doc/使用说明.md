# SemiRisk 使用说明 (Windows 版)

## 1. 架构说明

当前版本为前后端分离 + Maven 多模块微服务结构：

- `semirisk-ui`：Vue 3 + Vite 前端，默认端口 `5173`
- `semirisk-gateway`：API 网关和兼容入口，默认端口 `8080`
- `semirisk-data-service`：公开源爬虫与近三天数据刷新服务，默认端口 `8081`
- `semirisk-risk-service`：AI 风险自动测算服务，默认端口 `8082`
- `semirisk-ai-service`：AI API Key 配置与报告分析预留服务，默认端口 `8083`
- `semirisk-alert-service`：告警读写微服务，默认端口 `8084`
- `semirisk-report-service`：报告任务微服务，默认端口 `8085`
- `semirisk-common`：公共父模块，按职责拆分为 `semirisk-common-core`、`semirisk-common-db`、`semirisk-common-middleware`、`semirisk-common-ai`

### 1.2 基础设施组件

#### 1.2.1 线程池隔离（ThreadPoolConfig.java）

6 个独立线程池按业务域隔离，避免相互阻塞：

| Bean 名称 | 核心线程 | 最大线程 | 队列容量 | 拒绝策略 | 优雅关闭 |
|---|---|---|---|---|---|
| `semiriskCrawlerPool` | 4 | 8 | 100 | CallerRunsPolicy | 30s |
| `semiriskAiPool` | 2 | 4 | 50 | CallerRunsPolicy | 60s |
| `semiriskQueryPool` | 8 | 16 | 200 | DiscardOldestPolicy | 30s |
| `semiriskReportPool` | 2 | 4 | 20 | DiscardPolicy | 120s |
| `semiriskUploadPool` | 2 | 4 | 50 | CallerRunsPolicy | 60s |
| `semiriskAlertPool` | 2 | 4 | 100 | CallerRunsPolicy | 30s |

共享 `HttpClient` 单例，连接超时 8 秒。

#### 1.2.2 Redis 缓存（RedisCacheConfig.java）

4 个命名缓存，各自独立 TTL：

| 缓存名 | TTL | 用途 |
|---|---|---|
| `dashboard:overview` | 60 秒 | Dashboard KPI 聚合结果 |
| `enterprise` | 300 秒（5 分钟） | 企业画像搜索结果 |
| `risk:snapshot` | 30 秒 | 风险快照 |
| `knowledge` | 120 秒（2 分钟） | 知识库检索结果 |
| 默认 | 60 秒 | 其他缓存 |

#### 1.2.3 RabbitMQ 消息队列（RabbitMqConfig.java）

3 个持久化队列，其中 2 个配死信队列（DLQ）：

| 队列名 | Exchange | Routing Key | DLQ | 用途 |
|---|---|---|---|---|
| `ai.evaluate.queue` | `ai.evaluate.exchange` | `ai.evaluate` | `ai.evaluate.dlq` | 上传文件 AI 评估 |
| `report.generate.queue` | `report.exchange` | `report.generate` | `report.generate.dlq` | 报告生成任务 |
| `crawler.sync.queue` | `crawler.sync.exchange` | `crawler.sync` | 无 | Gateway ↔ DataService 爬虫同步 |

#### 1.2.4 Sentinel 流控与熔断（SentinelRuleConfig.java）

| 规则类型 | 资源名 | 阈值 | 说明 |
|---|---|---|---|
| 流控 | `auth.login` | 20 QPS | 登录接口限流 |
| 流控 | `dashboard.overview` | 50 QPS | Dashboard 限流 |
| 流控 | `knowledge.ask` | 5 QPS | 知识库 AI 问答限流（保护 LLM 配额） |
| 流控 | `reports.create` | 3 QPS | 报告生成限流（防止 LLM 并发过载） |
| 熔断 | `knowledge.ask` | 3s 慢调用超 60% | 熔断 10 秒 |
| 熔断 | `reports.create` | 异常率 50% | 熔断 30 秒 |

#### 1.2.5 限流与幂等

- **滑动窗口限流**（RateLimitingFilter）：基于 Redis Sorted Set，作用于 `/api/auth/register`（60 秒 2 次）和 `/api/auth/send-verification-code`（60 秒 1 次）。Redis 故障时放行（记录警告日志）。
- **请求幂等**（IdempotencyFilter）：POST/PUT 请求携带 `Idempotency-Key` 请求头，Redis SET NX 5 分钟 TTL。重复提交返回 HTTP 409 Conflict。排除 `/api/auth/login`、`/api/auth/register`、`/api/dashboard/`、`/api/knowledge/preview/`。

#### 1.2.6 分布式锁（DistributedLockManager.java）

基于 Redisson `RLock`，前缀 `semirisk:lock:`。提供两种模式：
- `executeWithLock(lockName, waitMs, leaseMs, task)` — 可配置等待/租约时间
- `executeWithLockSimple(lockName, task)` — 无限等待，适用于串行化场景

#### 1.2.7 安全响应头（TraceIdFilter.java）

每个请求自动注入：

| 响应头 | 值 |
|---|---|
| `X-Trace-Id` | UUID（请求无则自动生成） |
| `Content-Security-Policy` | `default-src 'self'; script-src 'self' https://cdn.tailwindcss.com https://code.iconify.design; style-src 'self' 'unsafe-inline' https://cdn.tailwindcss.com https://code.iconify.design; img-src 'self' data: https:; frame-ancestors 'none'; form-action 'self'` |
| `X-Frame-Options` | `DENY` |
| `X-Content-Type-Options` | `nosniff` |
| `Referrer-Policy` | `no-referrer` |
| `Permissions-Policy` | `camera=(), microphone=(), geolocation=()` |

#### 1.2.8 输入清洗（InputSanitizer.java）

统一 XSS 和控制字符过滤，正则白名单校验用户名、QQ 邮箱、角色、密码强度。

#### 1.2.9 向量检索（VectorSearchService.java）

Phase 3 已实现：ES `dense_vector` 字段 + RRF（Reciprocal Rank Fusion）混合搜索。关键词 `multi_match`（`title^3, content^2`）与向量相似度融合。未配置 Embedding 端点时自动回退纯关键词搜索。

#### 1.2.10 ES 批量写入（ElasticSearchBulkWriter.java）

内存缓冲区 `ConcurrentLinkedQueue`，100 条 / 5 秒自动刷写，2000 上限防 OOM。ES 故障自动熔断 60 秒，失败文档重新入队。

## 2. 环境要求

- **Java 21** 或更高（推荐 JDK 21，配置 `JAVA_HOME` 环境变量）
- **Node.js 20** 或更高（用于前端）
- **npm**（随 Node.js 一起安装）
- **Maven** 使用仓库自带 `mvnw.cmd`
- **OpenSSH**（Windows 10+ 自带，或在 PowerShell 中运行 `Get-WindowsCapability -Online | Where-Object Name -like 'OpenSSH.Client*'` 安装）
- **PuTTY / WinSCP（可选）**：用于管理 SSH 隧道

## 10. 常见问题排查

| 问题 | 原因 | 解决方法 |
|---|---|---|
| 中间件不可达 | SSH 隧道断开 | 重新建立 SSH 隧道 |
| 端口被占用 | 之前的 Java/Node 进程未退出 | `netstat -ano | findstr :8080` 找到 PID 后 `taskkill /F /PID <pid>` |
| AI 问答返回"未配置 API Key" | `.env.local` 缺少 Key | 填写 `SEMIRISK_AI_API_KEY` 并重启 Gateway |
| 前端 404 | 未构建或 Vite 未启动 | `npm run dev` 或 `npm run build` |
| MVNW 无法执行 | PowerShell 执行策略限制 | 以管理员运行：`Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` |
| Maven 找不到模块 | 未先执行 install | 先运行 `.\mvnw.cmd -DskipTests install` |
| Nacos 日志冲突 | Nacos 内置 logback 冲突 | 已通过 `nacos.logging.default.config.enabled=false` 修复 |
| 登录失败 | CSRF Token 过期 | 前端自动刷新；手动测试时先 GET `/api/auth/csrf` |
| ES 写入失败 | ES 不可达 | 检查隧道 9200 端口；不影响主流程 |
| AI 返回 flash 模型而非 v4-pro | 旧版本 `resolveDeepSeekApiModel` 将 `deepseekv4-pro` 映射为 `deepseek-chat`（通用路由别名） | 已修复，当前精确请求 `deepseek-v4-pro`；如仍异常请检查环境变量 `SEMIRISK_AI_MODEL` 值 |

## 13. 基础设施与安全特性

### 13.1 请求限流

注册和验证码接口受滑动窗口限流保护（详见 1.2.5）：
- 注册：60 秒内最多 2 次
- 发送验证码：60 秒内最多 1 次
- 超限返回 HTTP 429

### 13.2 请求幂等

对 POST/PUT 请求支持幂等校验（详见 1.2.5）：
- 客户端在请求头中添加 `Idempotency-Key: <unique-id>`
- 5 分钟内相同 Key 的重复请求返回 HTTP 409
- 适用于上传、报告生成等关键操作

### 13.3 分布式锁

多实例部署时，关键定时任务（爬虫同步、数据归档）通过 Redisson 分布式锁保证只有一个实例执行（详见 1.2.6）。

### 13.4 安全响应头

所有响应自动注入 CSP、X-Frame-Options DENY、nosniff 等安全头（详见 1.2.7），防止 XSS、点击劫持等攻击。

### 13.5 向量检索

配置 `SEMIRISK_EMBEDDING_ENDPOINT` 和 `SEMIRISK_EMBEDDING_API_KEY` 后，知识库搜索自动启用向量检索，与关键词搜索通过 RRF 融合排序（详见 1.2.9）。

### 13.6 AI 结构化输出

AI 服务使用 DeepSeek JSON Schema `response_format: { strict: true }` 确保输出 100% 格式稳定，无需 Markdown 清洗。支持 4 个场景：报告生成、文件评估、本日风险分析、问答（详见 `semirisk-ai-service` 的 `AiStructuredOutputService`）。
