# SemiRisk 使用说明

## 1. 架构说明

当前版本为前后端分离 + Maven 多模块微服务结构：

- `semirisk-ui`：Vue 3 + Vite 前端，默认端口 `5173`
- `semirisk-gateway`：API 网关和兼容入口，默认端口 `8080`
- `semirisk-data-service`：公开源爬虫与近三天数据刷新服务，默认端口 `8081`
- `semirisk-risk-service`：AI 风险自动测算服务，默认端口 `8082`
- `semirisk-ai-service`：AI API Key 配置与报告分析预留服务，默认端口 `8083`
- `semirisk-alert-service`：告警读写微服务，默认端口 `8084`
- `semirisk-report-service`：报告任务微服务，默认端口 `8085`
- `semirisk-common`：公共父模块，按职责拆分为 `semirisk-common-core`、`semirisk-common-db`、`semirisk-common-middleware`、`semirisk-common-ai`

### 1.1 Gateway 服务层架构

Gateway 的业务逻辑按领域职责拆分为多个 Spring Service：

```text
semirisk-gateway/src/main/java/com/semirisk/service/
├── SemiRiskStore.java       # 核心协调器：用户认证、风险快照、告警、上传、报告、Dashboard
├── TranslationService.java  # 中英文翻译：标题关键词翻译、等级/状态/维度名称映射
├── GisService.java          # GIS 服务：地理编码、风险点位散布、供应链路径生成
├── EnterpriseService.java   # 企业画像：公开公司数据库(15家)、Wikipedia查询、互联网搜索
├── AiChatService.java       # AI 对话：DeepSeek API调用、答案解析、知识问答构建
└── HealthProbeService.java  # 健康探测：MySQL/Redis/ES/MinIO/RabbitMQ/Nacos连通性
```

各服务职责边界：

| 服务 | 核心方法 | 说明 |
|---|---|---|
| `TranslationService` | `titleTranslation()`, `translateEnglishTitle()`, `translateChineseTitle()`, `levelName()`, `statusName()`, `dimensionName()` | 公开源标题中英双向翻译（关键词规则匹配），风险等级（高危/中危/低危）、状态（未处理/处理中/已忽略）、维度名的英文映射 |
| `GisService` | `buildGisData()`, `gisPoints()`, `gisRoutes()`, `geocodeSignal()` | 将公开源信号通过关键词匹配到 36 个全球地理区域（含坐标），生成 GIS 点位和风险传输路径，支持螺旋散布避免叠压 |
| `EnterpriseService` | `buildBusinessWithWiki()`, `internetSearches()`, `internetSearchResults()`, `enterpriseCatalog()`, `persistSearchedEnterprise()` | 内置 15 家半导体头部企业公开信息（TSMC/Samsung/ASML/NVIDIA 等），未命中时查 Wikipedia 英文百科补充，提供企查查/天眼查/Bing/路透社/SEC 外链和 DuckDuckGo 兜底搜索 |
| `AiChatService` | `callDeepSeek()`, `splitAnswer()`, `resolveDeepSeekApiModel()`, `localKnowledgeLines()`, `buildKnowledgeAnswerPayload()` | 封装 DeepSeek Chat Completions 调用（含系统提示词、超时、错误处理），答案去除 Markdown 并结构化为段落，组装知识问答响应体（含引用/链路/token用量） |
| `HealthProbeService` | `resolveMiddlewareHost()`, 各中间件探测方法 | 依次尝试 localhost（本地隧道）和 VM IP，返回真实延迟和可达状态 |

## 2. 环境要求

- Java 21 或更高
- Node.js 20 或更高
- npm
- Maven 使用仓库自带 `mvnw`

## 3. 启动顺序（重要）

系统启动必须按以下顺序执行，否则服务间依赖将导致启动失败或功能异常：

```text
步骤 1: SSH 隧道（如需通过跳板机访问中间件）
步骤 2: 验证中间件连通性
步骤 3: 编译打包
步骤 4: 启动后端服务（有严格顺序）
步骤 5: 启动前端
步骤 6: 浏览器登录验证
```

### 3.1 步骤 1：建立 SSH 隧道（本机无法直连 VM 时必须）

```bash
SEMIRISK_SSH_JUMP_PASSWORD=123qwe SEMIRISK_VM_PASSWORD=123123 bash script/start-vm-tunnels.sh
```

隧道在 screen 后台运行，不要关闭终端。隧道建立后所有中间件端口映射到 `127.0.0.1`。

### 3.2 步骤 2：验证中间件

```bash
VM_HOST=127.0.0.1 bash script/check-vm-middleware.sh
```

确认输出中 MySQL(3306)、Redis(6379)、ES(9200)、MinIO(9000)、RabbitMQ(5672)、Nacos(8848) 均为 OK。

### 3.3 步骤 3：编译打包

```bash
./mvnw -DskipTests install
```

此步骤会编译所有模块并生成 JAR，后续启动脚本依赖此产物。

### 3.4 步骤 4：启动后端服务

**方式一（推荐）：使用一键脚本**

```bash
bash script/start-backend-services.sh
```

脚本会自动加载 `.env.local`，按正确顺序启动所有服务。

**方式二：手动逐个启动**

后端服务启动顺序如下，**Gateway 必须最后启动**（它依赖其他服务的数据）：

| 启动顺序 | 服务 | 端口 | 说明 |
|---|---|---|---|
| ① | semirisk-data-service | 8081 | 公开源爬虫，启动后立即采集数据 |
| ② | semirisk-risk-service | 8082 | 风险测算，依赖 data-service 的爬虫数据 |
| ③ | semirisk-ai-service | 8083 | AI 报告生成，依赖 data-service 数据 |
| ④ | semirisk-alert-service | 8084 | 告警服务 |
| ⑤ | semirisk-report-service | 8085 | 报告导出服务 |
| ⑥ | semirisk-gateway | 8080 | **最后启动**，聚合所有服务数据，提供统一 API |

手动启动命令：

```bash
# 确保 .env.local 已加载
export $(grep -v '^#' .env.local | xargs)

# ① data-service（终端 1）
./mvnw -pl semirisk-services/semirisk-data-service spring-boot:run

# ② risk-service（终端 2）
./mvnw -pl semirisk-services/semirisk-risk-service spring-boot:run

# ③ ai-service（终端 3）
./mvnw -pl semirisk-services/semirisk-ai-service spring-boot:run

# ④ alert-service（终端 4）
./mvnw -pl semirisk-services/semirisk-alert-service spring-boot:run

# ⑤ report-service（终端 5）
./mvnw -pl semirisk-services/semirisk-report-service spring-boot:run

# ⑥ gateway（终端 6，最后启动）
./mvnw -pl semirisk-services/semirisk-gateway spring-boot:run
```

**最小启动（仅 Gateway）：** 如果只需要快速验证登录和基本页面，可以只启动 Gateway：

```bash
./mvnw -pl semirisk-services/semirisk-gateway spring-boot:run
```

此模式下公开源数据为空（需 data-service 采集），但登录、Dashboard 框架、系统管理可用。

### 3.5 步骤 5：启动前端

```bash
bash script/start-ui.sh
```

或手动：

```bash
cd semirisk-ui
npm install   # 首次或依赖变更时
npm run dev
```

### 3.6 步骤 6：浏览器访问

```text
http://localhost:5173    ← Vue 开发模式（推荐开发时使用）
http://localhost:8080    ← Gateway 托管模式（需先 npm run build）
```

使用管理员账号登录：

```text
账号：kaduoxli
密码：123qwe123
```

### 3.7 停止服务

停止后端（screen 模式）：

```bash
screen -ls | grep semirisk | awk '{print $1}' | xargs -I{} screen -S {} -X quit
```

停止隧道：

```bash
bash script/stop-vm-tunnels.sh
```

## 5. 中间件脚本

虚拟机 `192.168.101.130` 还未连接时，不需要启动中间件也可以本地演示。后续连接 VM 后，在 VM 上运行：

```bash
./script/install-vm-middleware.sh
```

本次部署包保留在 VM 的 `/opt/semirisk/packages/semirisk-middleware-deploy.tgz`，服务目录为 `/opt/semirisk`。当前 VM 访问 Docker Hub 不稳定，RabbitMQ 使用宿主机服务模式，其余中间件使用 Docker Compose：

```bash
sudo env PROJECT_DIR=/opt/semirisk/middleware RABBITMQ_MODE=host bash /opt/semirisk/script/install-vm-middleware.sh
```

当前网络需要经过 `172.16.0.151` 中转时，本机不能直接访问 `192.168.101.130`。先在本机项目根目录启动 SSH 隧道：

```bash
SEMIRISK_SSH_JUMP_PASSWORD=*** SEMIRISK_VM_PASSWORD=*** ./script/start-vm-tunnels.sh
```

如果不设置密码环境变量，脚本会进入交互模式，需要保持该终端窗口打开。隧道建立后，本机端口映射为：

```text
127.0.0.1:3306  -> VM MySQL
127.0.0.1:6379  -> VM Redis
127.0.0.1:9200  -> VM Elasticsearch
127.0.0.1:9000  -> VM MinIO API
127.0.0.1:9001  -> VM MinIO Console
127.0.0.1:5672  -> VM RabbitMQ
127.0.0.1:15672 -> VM RabbitMQ Console
127.0.0.1:8848  -> VM Nacos
```

检查隧道连通性：

```bash
VM_HOST=127.0.0.1 ./script/check-vm-middleware.sh
```

停止隧道：

```bash
./script/stop-vm-tunnels.sh
```

脚本会启动 MySQL、Redis、Elasticsearch、MinIO、RabbitMQ、Nacos，并自动导入：

```text
script/semirisk-schema.sql
```

当前风险类页面采用“公开源爬虫优先”：`semirisk-data-service` 成功采集国内外公开 RSS/Atom 后，Dashboard、预警中心、GIS、知识库和风险分析均使用近三天公开源文章、原文链接、发布时间和规则评分。公开源不可达时页面显示待采集或采集失败，不再伪造实时风险事件。

Gateway 已引入 Flyway，迁移脚本位置：

```text
semirisk-services/semirisk-gateway/src/main/resources/db/migration/V1__init_schema.sql
```

本地默认 `SEMIRISK_FLYWAY_ENABLED=false`，连接 VM MySQL 后可设置为 `true` 自动迁移。

本机检查连通性：

```bash
./script/check-vm-middleware.sh
```

## 6. 公开源实时爬取与 12 小时自动刷新

- 数据服务启动时会立即从公开 RSS/Atom 源实时爬取一次，不使用写死记录
- 数据服务每 12 小时自动重新爬取一次，默认保留近三天真实公开源条目
- 用户调用 `/api/crawler/refresh` 时会立即重新爬取公开源
- Gateway 只同步 `semirisk-data-service` 的真实爬取结果，不再用空数据定时覆盖已采集快照
- 风险服务基于当前爬虫快照自动测算风险；公开源不可达时显示待采集，不伪造事件
- 风险测算服务、AI 报告生成服务和 Gateway 定时刷新点均统一为 12 小时；页面手动操作仍会立即调用对应 API。AI 本日报告真实聚合公开源并调用 DeepSeek 生成，持久化于 `ai_report` 表
- Redis 可用时，登录失败计数和账号锁定优先写入 Redis；Redis 不可用时自动回退内存计数

也可以调用下面接口手动刷新公开源：

```bash
curl -X POST http://localhost:8081/api/crawler/refresh
```

或在 Vue 首页点击“立即重新测算”手动触发 Gateway 聚合。`/api/crawler/records/today` 为兼容旧路径，当前返回的是近三天窗口内记录。

## 7. AI API Key 配置

默认模型：

- 模型：`deepseekv4-pro`
- Endpoint：`https://api.deepseek.com/v1`
- 密钥：通过环境变量 `SEMIRISK_AI_API_KEY` 注入

进入 Vue 前端的“系统管理”页面，也可以在线填写：

- 模型名称
- Endpoint
- API Key

点击“保存配置”后，后端会脱敏保存 API Key，原始 Key 仅保存在运行期内存中用于调用。知识库页面的 AI 智能体会先执行本地知识库、公开源和 Elasticsearch RAG 检索，再调用 DeepSeek Chat Completions；未配置 Key 或调用失败时才回退本地摘要。

如果通过 Gateway 端口访问页面，需先构建前端：

```bash
cd semirisk-ui
npm run build
```

Gateway 已配置为优先托管 `semirisk-ui/dist`，因此 `http://localhost:8080` 和 `http://localhost:5173` 都会进入同一套 Vue 登录逻辑，不再返回旧静态登录页。

## 8. 知识库 AI 问答

进入“知识库”页面后，在“AI 知识库智能体”输入问题，例如：

```text
当前半导体供应链最需要关注什么风险？
```

点击“提问”后前端调用：

```text
POST /api/knowledge/ask
```

返回内容包含：

- 回答正文
- 检索链路
- 引用原文链接
- 模型状态
- `aiCalled` 和 `usage.totalTokens`，用于确认是否真实消耗 AI Token

知识库页面只保留 AI 智能体入口，不再展示下方检索卡片。后端会结合本地知识库、公开源记录和 Elasticsearch 结果组织上下文；配置 API Key 后会真实调用 DeepSeek Chat Completions。`deepseekv4-pro` 作为业务显示模型保留，当前接口实际使用 DeepSeek 兼容模型 `deepseek-chat` 发起请求，返回中会显示实际 `apiModel`。

## 9. 登录、Token 与权限

未登录用户只能访问 Vue 首页风险总览，左下角账户区域提供“登录”和“注册”入口；顶部只显示未登录提示，不再重复放置登录/注册按钮。系统不再使用 Cookie 登录态，登录和注册成功后返回 Bearer Token：

```json
{
  "token": "opaque-token",
  "expiresAt": "2026-06-04T10:00:00Z",
  "user": {
    "username": "your_user",
    "role": "ADMIN",
    "modules": ["dashboard", "system"]
  }
}
```

Token 默认 30 分钟滑动有效：

- 30 分钟内刷新任意页面：前端用本地 Token 调用 `/api/auth/me`，恢复当前路由并重新加载当前页面数据。
- 处于系统页面并持续操作时：每次成功 API 请求都会刷新本地过期时间，服务端也会滑动续期。
- 超过 30 分钟无任何接口交互后刷新页面：前端清理本地 Token，回到首页并要求重新登录。
- 正常路由跳转：复用当前 Token，不需要重新登录。

所有受保护 API 都需要：

```http
Authorization: Bearer <token>
```

所有 POST、PUT、DELETE 请求还需要先获取 CSRF Token：

```bash
CSRF=$(curl -s http://localhost:8080/api/auth/csrf | sed -n 's/.*"token":"\([^"]*\)".*/\1/p')
```

并在写请求中携带：

```http
X-CSRF-Token: <csrf-token>
```

注册首个管理员的命令示例：

```bash
CSRF=$(curl -s http://localhost:8080/api/auth/csrf | sed -n 's/.*"token":"\([^"]*\)".*/\1/p')
curl -s -X POST http://localhost:8080/api/auth/register \
  -H "Content-Type: application/json" \
  -H "X-CSRF-Token: ${CSRF}" \
  -d '{"username":"semirisk_admin","email":"123456@qq.com","displayName":"系统管理员","password":"Password123"}'
```

登录命令示例：

```bash
CSRF=$(curl -s http://localhost:8080/api/auth/csrf | sed -n 's/.*"token":"\([^"]*\)".*/\1/p')
curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -H "X-CSRF-Token: ${CSRF}" \
  -d '{"username":"semirisk_admin","password":"Password123","rememberMe":false}'
```

当前权限矩阵：

| 角色 | 权限模块 |
|---|---|
| `ADMIN` | 首页、上传、分析、详情、报告、告警、GIS、企业画像、知识库、系统管理 |
| `ANALYST` | 首页、分析、详情、报告、告警、GIS、企业画像、知识库 |
| `OPERATOR` | 首页、上传、告警、GIS、企业画像、知识库 |

后端除以下公开接口外，其余 `/api/**` 均需要登录态：

- `/api/auth/**`
- `/api/dashboard/overview`
- `/api/risk-score/today`

## 10. 预警中心详情

预警中心的“详情”按钮只展示当前选中告警本身，不再展示通用风险 SOP、定损、传导路径等扩展内容。详情接口为：

```text
GET /api/risk/events/{id}
```

返回核心字段：

- `id`、`level`、`status`、`type`、`riskScore`
- `source`、`sourceUrl`、`firstSeen`
- `originalTitle`、`translation.zh`、`translation.en`
- `bilingualRows`：中英文对照表

翻译为本地关键词规则译文，用于中英文对照和快速理解；事实核验仍以 `sourceUrl` 原文为准。

## 10.1 页面交互优化

- 首页风险总览的公开源信号固定高度分页展示，不再无限向下滚动。
- 数据上传页说明清洗对象和目的：供应商、BOM、物流节点、合同交期、公开研报等，清洗结果用于评分、预警、画像和报告。
- 风险详情页左侧为告警概览分页，右侧为点击后生成的单条解释。
- 企业画像右侧为工商、雷达、拓扑、历史事件四页切换。
- GIS 地图使用 3D 透视面板，默认自动旋转；鼠标拖动后进入手动旋转，点击点位会在地图内弹窗显示详情。
- 系统管理日志固定高度分页，可按日期筛选。

### 16.8 常见问题排查

| 问题 | 原因 | 解决 |
|---|---|---|
| MySQL 不可达 | 隧道断开 | 重新执行 `start-vm-tunnels.sh` |
| Nacos 日志冲突 | Nacos 内置 logback 与项目冲突 | 已通过 `nacos.logging.default.config.enabled=false` 修复 |
| 登录失败 | CSRF Token 过期 | 前端自动刷新；手动测试时先 GET `/api/auth/csrf` |
| AI 问答返回"未配置 API Key" | `.env.local` 缺少 Key | 填写 `SEMIRISK_AI_API_KEY` 并重启 |
| 前端 404 | 未构建或 Vite 未启动 | `npm run dev` 或 `npm run build` |
| 端口被占用 | 之前的进程未退出 | `lsof -i :8080` 查看并 kill |
| ES 写入失败 | ES 不可达 | 检查隧道 9200 端口；不影响主流程 |

## 18. SSH 网络拓扑

```text
开发机 (macOS/Linux)
    │
    │ SSH (22) + Port Forwarding
    ▼
172.16.0.151 (跳板机, 用户: kaduox)
    │
    │ SSH (22) + Port Forwarding
    ▼
192.168.101.130 (中间件 VM, 用户: kaduox)
    ├── MySQL      :3306
    ├── Redis      :6379
    ├── Elasticsearch :9200
    ├── MinIO API  :9000
    ├── MinIO Console :9001
    ├── RabbitMQ   :5672
    ├── RabbitMQ Console :15672
    ├── Nacos      :8848 / 9848(gRPC)
    └── Zipkin     :9411
```

`~/.ssh/config` 中已配置 `semirisk-vm` 别名：

```text
Host semirisk-vm
    HostName 192.168.101.130
    User kaduox
    ProxyJump kaduox@172.16.0.151
```

手动 SSH 连接 VM：`ssh semirisk-vm`
