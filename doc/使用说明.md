# SemiRisk 使用说明 (Windows 版)

## 1. 架构说明

当前版本为前后端分离 + Maven 多模块微服务结构：

- `semirisk-ui`：Vue 3 + Vite 前端，默认端口 `5173`
- `semirisk-gateway`：API 网关和兼容入口，默认端口 `8080`
- `semirisk-data-service`：公开源爬虫与近三天数据刷新服务，默认端口 `8081`
- `semirisk-risk-service`：AI 风险自动测算服务，默认端口 `8082`
- `semirisk-ai-service`：AI API Key 配置与报告分析预留服务，默认端口 `8083`
- `semirisk-alert-service`：告警读写微服务，默认端口 `8084`
- `semirisk-report-service`：报告任务微服务，默认端口 `8085`
- `semirisk-common`：公共父模块，按职责拆分为 `semirisk-common-core`、`semirisk-common-db`、`semirisk-common-middleware`、`semirisk-common-ai`

### 1.1 Gateway 服务层架构

Gateway 的业务逻辑按领域职责拆分为多个 Spring Service，数据模型统一收拢到 `com.semirisk.model` 包：

```
semirisk-gateway/src/main/java/com/semirisk/
├── model/                              # 共享数据模型
│   ├── UserAccount.java               # 用户账户
│   ├── LoginState.java                # 登录状态
│   ├── RiskAlert.java                 # 风险告警
│   ├── CrawlerSignal.java             # 爬虫信号
│   ├── DailyRiskSnapshot.java         # 日度风险快照
│   ├── UploadTask.java                # 上传任务
│   ├── ReportJob.java                 # 报告任务
│   ├── SystemUser.java                # 系统用户
│   └── AiModelConfig.java             # AI 模型配置
└── service/
    ├── SemiRiskStore.java             # 核心协调器：风险快照、信号持久化、定时任务
    ├── AuthService.java               # 用户认证、Token、防爆锁
    ├── AlertService.java              # 告警查询、状态流转、公开源告警派生
    ├── UploadService.java             # 上传任务、文件解析进度、SSE 推送
    ├── ReportService.java             # 报告调度、AI 报告生成、异步执行
    ├── DashboardService.java          # Dashboard KPI、时间窗口分析
    ├── SystemManagementService.java   # 系统用户、模型配置、审计日志
    ├── TranslationService.java        # 中英双向翻译、枚举映射
    ├── GisService.java                # 地理编码、GIS 点位、风险路径
    ├── EnterpriseService.java         # 企业画像、Wikipedia、搜索
    ├── AiChatService.java             # DeepSeek API、知识问答
    └── HealthProbeService.java        # 中间件连通性探测
```

各服务职责边界：

| 服务 | 核心方法 | 说明 |
|---|---|---|
| `TranslationService` | `titleTranslation()`, `translateEnglishTitle()`, `translateChineseTitle()`, `levelName()`, `statusName()`, `dimensionName()` | 公开源标题中英双向翻译，风险等级/状态/维度名的英文映射 |
| `GisService` | `buildGisData()`, `gisPoints()`, `gisRoutes()`, `geocodeSignal()` | 将公开源信号通过关键词匹配到 36 个全球地理区域，生成 GIS 点位和风险传输路径 |
| `EnterpriseService` | `buildBusinessWithWiki()`, `internetSearches()`, `internetSearchResults()`, `enterpriseCatalog()` | 内置 15 家半导体头部企业公开信息，未命中时查 Wikipedia 补充 |
| `AiChatService` | `callDeepSeek()`, `splitAnswer()`, `resolveDeepSeekApiModel()`, `localKnowledgeLines()` | 封装 DeepSeek Chat Completions 调用，答案去除 Markdown 并结构化为段落 |
| `HealthProbeService` | `resolveMiddlewareHost()`, 各中间件探测方法 | 依次尝试 localhost 和 VM IP，返回真实延迟和可达状态 |

## 2. 环境要求

- **Java 21** 或更高（推荐 JDK 21，配置 `JAVA_HOME` 环境变量）
- **Node.js 20** 或更高（用于前端）
- **npm**（随 Node.js 一起安装）
- **Maven** 使用仓库自带 `mvnw.cmd`
- **OpenSSH**（Windows 10+ 自带，或在 PowerShell 中运行 `Get-WindowsCapability -Online | Where-Object Name -like 'OpenSSH.Client*'` 安装）
- **PuTTY / WinSCP（可选）**：用于管理 SSH 隧道

### 3.2 启动 SSH 隧道（如需连接虚拟机中间件）

虚拟机中间件在 `192.168.101.130`，本机（Windows）需要先通过跳板机 `172.16.0.151` 建立 SSH 隧道。

**方式一：使用一键脚本（推荐）**

在 Git Bash 或 PowerShell 中执行（需要安装 sshpass）：


**方式二：手动 SSH 隧道（PowerShell）**

1. 打开 PowerShell，先连接跳板机并建立端口转发：

```powershell
ssh -N -J kaduox@172.16.0.151 ^
  -L 3306:127.0.0.1:3306 ^
  -L 6379:127.0.0.1:6379 ^
  -L 9200:127.0.0.1:9200 ^
  -L 9000:127.0.0.1:9000 ^
  -L 9001:127.0.0.1:9001 ^
  -L 5672:127.0.0.1:5672 ^
  -L 15672:127.0.0.1:15672 ^
  -L 8848:127.0.0.1:8848 ^
  -L 9848:127.0.0.1:9848 ^
  -L 9411:127.0.0.1:9411 ^
  kaduox@192.168.101.130
```

密码依次输入：跳板机密码 `123qwe`，VM 密码 `123123`。

2. 保持此 PowerShell 窗口打开，隧道才会持续有效。

3. 隧道建立后，所有中间件端口映射到 `127.0.0.1`。在另一个 PowerShell 窗口中验证连通性：

```powershell

# 验证 Redis
Test-NetConnection 127.0.0.1 -Port 6379

# 验证 Elasticsearch

```

**方式三：使用 PowerShell SSH 控制连接（持久化）**

```powershell
    "-J kaduox@172.16.0.151",
    "-L 3306:127.0.0.1:3306",
    "-L 6379:127.0.0.1:6379",
    "-L 9200:127.0.0.1:9200",
    "-L 9000:127.0.0.1:9000",
    "-L 9001:127.0.0.1:9001",
    "-L 5672:127.0.0.1:5672",
    "-L 15672:127.0.0.1:15672",
    "-L 8848:127.0.0.1:8848",
    "-L 9848:127.0.0.1:9848",
    "-L 9411:127.0.0.1:9411",
    "kaduox@192.168.101.130"

# 等待隧道建立

# 验证
```

## 4. 启动后端服务

### 4.1 编译打包

在 PowerShell 中执行：

```powershell
.\mvnw.cmd -DskipTests install
```

此步骤会编译所有模块并生成 JAR 文件，后续启动脚本依赖此产物。

### 4.2 启动全部后端服务

**方式一（推荐）：使用一键脚本**

如果安装了 Git Bash：

```bash
bash script/start-backend-services.sh
```

如果 Windows 上只有 PowerShell，使用 Maven 逐个启动（见方式二）。

**方式二：PowerShell 逐个启动（推荐 Windows 用户）**

后端服务启动顺序如下，**Gateway 必须最后启动**：

| 启动顺序 | 服务 | 端口 | 说明 |
|---|---|---|---|
| ① | semirisk-data-service | 8081 | 公开源爬虫 |
| ② | semirisk-risk-service | 8082 | 风险测算 |
| ③ | semirisk-ai-service | 8083 | AI 报告 |
| ④ | semirisk-alert-service | 8084 | 告警服务 |
| ⑤ | semirisk-report-service | 8085 | 报告导出 |
| ⑥ | semirisk-gateway | 8080 | **最后启动**，聚合数据 |

逐个启动命令（每个服务开一个 PowerShell 窗口）：

```powershell
# 窗口 1：data-service
.\mvnw.cmd -pl semirisk-services/semirisk-data-service spring-boot:run

# 窗口 2：risk-service
.\mvnw.cmd -pl semirisk-services/semirisk-risk-service spring-boot:run

# 窗口 3：ai-service
.\mvnw.cmd -pl semirisk-services/semirisk-ai-service spring-boot:run

# 窗口 4：alert-service
.\mvnw.cmd -pl semirisk-services/semirisk-alert-service spring-boot:run

# 窗口 5：report-service
.\mvnw.cmd -pl semirisk-services/semirisk-report-service spring-boot:run

# 窗口 6：gateway（最后启动）
.\mvnw.cmd -pl semirisk-services/semirisk-gateway spring-boot:run
```

**最小启动（仅 Gateway）：** 快速验证登录和基本页面：

```powershell
.\mvnw.cmd -pl semirisk-services/semirisk-gateway spring-boot:run
```

### 4.3 停止后端服务

按 `Ctrl + C` 停止对应 PowerShell 窗口中的进程。

或使用 PowerShell 查找并终止 Java 进程：

```powershell
# 查找 Java 进程
Get-Process java | Where-Object { $_.MainWindowTitle -like "*semirisk*" }

# 停止所有 semirisk 相关 Java 进程
Get-Process java | Stop-Process -Force
```

## 10. 常见问题排查

| 问题 | 原因 | 解决方法 |
|---|---|---|
| 中间件不可达 | SSH 隧道断开 | 重新建立 SSH 隧道 |
| 端口被占用 | 之前的 Java/Node 进程未退出 | `netstat -ano | findstr :8080` 找到 PID 后 `taskkill /F /PID <pid>` |
| AI 问答返回"未配置 API Key" | `.env.local` 缺少 Key | 填写 `SEMIRISK_AI_API_KEY` 并重启 Gateway |
| 前端 404 | 未构建或 Vite 未启动 | `npm run dev` 或 `npm run build` |
| MVNW 无法执行 | PowerShell 执行策略限制 | 以管理员运行：`Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` |
| Maven 找不到模块 | 未先执行 install | 先运行 `.\mvnw.cmd -DskipTests install` |
| Nacos 日志冲突 | Nacos 内置 logback 冲突 | 已通过 `nacos.logging.default.config.enabled=false` 修复 |
| 登录失败 | CSRF Token 过期 | 前端自动刷新；手动测试时先 GET `/api/auth/csrf` |
| ES 写入失败 | ES 不可达 | 检查隧道 9200 端口；不影响主流程 |
