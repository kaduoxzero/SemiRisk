# SemiRisk 项目设计文档

## 1. 项目定位

SemiRisk 是面向半导体产业链的 AI 风险智能平台，覆盖数据采集、风险识别、AI 推理、预警派发、GIS 监控、企业画像、RAG 知识检索和报告生成闭环。

## 2. 技术栈

- 后端：Java 21、Spring Boot 3.5、Spring MVC、Validation、Actuator、Maven 多模块
- 前端：Vue 3、Vite、原生 CSS、Fetch API
- 构建：Maven Wrapper
- 状态：公开源爬虫数据驱动风险页面；MySQL、Redis 等中间件配置默认指向 `192.168.101.130`
- 部署：后端使用 `script/start-backend-services.sh`，前端使用 `script/start-ui.sh`

## 4. 架构设计

系统当前采用前后端分离 + 微服务模块架构：

- `semirisk-ui`：Vue 前端，统一访问 Gateway API
- `semirisk-gateway`：认证、页面 API 聚合、兼容入口、CORS，并优先托管 `semirisk-ui/dist` 避免返回旧静态页面
- `semirisk-data-service`：公开 RSS/Atom 实时爬虫、12 小时自动爬取、上传/ETL 扩展边界
- `semirisk-risk-service`：基于爬虫快照自动风险测算、风险评分 API
- `semirisk-ai-service`：AI API Key 管理、AI 本日风险报告真实生成（拉取公开源 + 调用 DeepSeek）、模型调用扩展
- `semirisk-alert-service`：告警查询和状态流转边界，优先面向 MySQL
- `semirisk-report-service`：报告异步任务边界，支持 PDF、DOCX、PPTX 文件流
- `semirisk-common-core`：公共响应结构、服务端口、角色权限策略
- `semirisk-common-db`：预编译 SQL 模板和数据库共享约束
- `semirisk-common-middleware`：虚拟机中间件默认地址与端口
- `semirisk-common-ai`：AI 默认模型、Endpoint、环境变量名

## 5. 中间件设计

所有中间件统一使用虚拟机 IP `192.168.101.130`：

- MySQL：业务数据持久化
- Redis Cluster（1 Master + 3 Replicas）：登录失败计数、Token、验证码、限流、幂等校验、短期任务状态
- Elasticsearch：知识库公开源索引与 RAG 文本检索
- MinIO：上传文件、PDF、报告文件存储
- RabbitMQ：ETL、报告生成和 Agent 异步任务
- Nacos：后续微服务注册配置中心

当本机无法直接访问 `192.168.101.130` 时，使用 `script/start-vm-tunnels.sh` 通过 `172.16.0.151` 中转，把 MySQL、Redis Cluster（6379-6382）、Elasticsearch、MinIO、RabbitMQ、Nacos 端口映射到 `127.0.0.1`；本地服务通过 `.env.local` 的 `SEMIRISK_MIDDLEWARE_HOST=127.0.0.1` 接入。

当前版本为保证本机可立即运行，公开源告警状态、报告进度仍保留内存兜底状态；登录注册以 MySQL `system_user` 为主路径，数据库不可达时启用本地兜底。系统启动管理员 `kaduoxli / 123qwe123` 每次 Gateway 启动都会初始化到内存，MySQL 可达时同步落库。风险页面不再回退固定演示风险，公开源不可达时显示待采集。Gateway 核心持久化接口采用数据库优先策略。Flyway 迁移脚本位于 `semirisk-services/semirisk-gateway/src/main/resources/db/migration`，连接 VM MySQL 后可通过 `SEMIRISK_FLYWAY_ENABLED=true` 自动迁移。知识库检索已接入 Elasticsearch，默认索引为 `semirisk_knowledge`。

## 6. 关键业务流

### 6.1 登录与防爆破

用户提交账号、密码、验证码标识。后端在 5 分钟窗口内统计失败次数，达到 5 次锁定 30 分钟。登录成功后签发 Bearer Token，默认 30 分钟滑动过期，不使用 Cookie 登录态。前端刷新页面时使用 Token 调用 `/api/auth/me` 恢复当前路由；Token 过期后清理本地状态并回到首页重新登录。每次成功 API 请求都会同步刷新本地过期时间，服务端也会滑动续期。

注册信息写入 MySQL `system_user`，密码使用 PBKDF2 哈希保存。Gateway 启动时通过 `BootstrapAdminProvisioner` 初始化最高权限账号；公开注册账号默认为 `OPERATOR`。Redis Cluster 可用时失败计数和锁定状态写入 Redis；集群不可用时回退到内存计数。

### 6.2 数据上传清洗

前端支持点击、拖拽文件上传。后端限制 50MB，创建上传任务；用户点击解析后任务进入“导入成功”状态。SSE 接口实时推送 AI 清洗日志。

### 6.3 爬虫与 12 小时刷新

`semirisk-data-service` 在服务启动时立即实时拉取公开 RSS/Atom 源（含政策法规源：联邦公报出口管制/半导体、WTO），抽取文章标题、原文链接、发布时间、风险维度和规则评分；之后每 12 小时自动重新爬取一次。手动调用 `/api/crawler/refresh` 会立即重新抓取公开源。爬虫默认只保留近三天内的公开源条目，每个来源最多保留 12 条，公开源不可达时仅返回采集失败状态，不伪造风险事件。Gateway 同步 data-service 的真实爬取结果后写入 MySQL（`crawler_signal`/`risk_snapshot`/`risk_alert`/`knowledge_doc`/`enterprise_record`），并据此聚合 Dashboard、告警、GIS、知识库、风险分析数据；`semirisk-risk-service` 与 AI 报告服务统一为 12 小时自动刷新，并可通过页面/接口手动立即触发。所有数据以 MySQL 为事实源，重启可恢复。

### 6.4 告警处理

预警中心从 `/api/alerts` 拉取公开源派生告警，支持关键词、等级、状态组合筛选。公开源告警包含原文链接，默认覆盖近三天成功采集记录，采集失败记录不作为真实告警展示。忽略告警会写入 Gateway 状态集，默认列表和计数器不再重复显示已忽略告警；批量处理只处理用户勾选的告警并流转为“处理中”。点击详情时 `/api/risk/events/{id}` 只返回该条告警本身，并提供 `translation` 与 `bilingualRows` 中英文对照，不返回 SOP、定损和传播路径。

### 6.5 报告生成

用户选择模板、语言、格式后创建异步报告任务（ID 前缀 `PR-`，时间戳格式 `yyyyMMddHHmmss`，如 `PR-20260618143022`）。前端轮询任务进度，完成后根据任务格式下载 PDF、DOCX 或 PPTX 文件。文件生成逻辑位于 `semirisk-common-core`，Gateway 和 report-service 复用。

### 6.6 知识库 AI 智能体

知识库页面提供 AI 智能体问答。前端调用 `/api/knowledge/ask`，Gateway 先同步公开源爬虫记录，并把成功采集记录写入 Elasticsearch 索引 `semirisk_knowledge`。问答优先组合本地知识库、ES `multi_match` 检索和公开源记录，返回原文引用、检索链路、模型状态与 token 用量；ES 不可用或无命中时回退公开源内存记录。配置 DeepSeek API Key 后真实调用 DeepSeek Chat Completions，未配置或调用失败时才回退本地 RAG 摘要。业务显示模型为 `deepseekv4-pro`，实际请求模型 `deepseek-v4-pro`（精确指定，不再使用 `deepseek-chat` 通用路由别名）。

### 6.7 AI API Key 启动即生效

API Key 通过环境变量 `SEMIRISK_AI_API_KEY` 或 `application.properties` 注入。Gateway 启动时 `SemiRiskStore.seedDefaultAiModel()` 自动将 Key 注入 `aiModelConfigs` 和 `aiModelApiKeys`，无需手动在系统管理页面配置。前端页面配置为可选覆盖方式。

当前 ES 方案支持文本关键词检索。向量检索功能已实现（`VectorSearchService`），基于 Elasticsearch `dense_vector` 字段，使用 RRF（Reciprocal Rank Fusion）融合关键词分与向量相似度分。启用条件：配置 `SEMIRISK_EMBEDDING_ENDPOINT` 和 `SEMIRISK_EMBEDDING_API_KEY` 环境变量。未配置时自动回退到纯关键词搜索。ES 批量写入由 `ElasticSearchBulkWriter` 管理：100 条 / 5 秒自动刷写，ES 故障自动熔断 60 秒，失败文档重新入队。

### 6.8 系统管理

系统管理页支持用户新增、启停、模型 Ping、Agent 触发、数据源重连等交互，均绑定后端 API。
系统管理页提供 AI 模型 Endpoint 与 API Key 配置入口，默认模型为 `deepseekv4-pro`，默认 Endpoint 为 `https://api.deepseek.com/v1`，Key 通过 `SEMIRISK_AI_API_KEY` 或页面配置注入，并在后端脱敏保存。日志面板按日期过滤并分页展示，每条本地审计日志会补齐当天日期，便于日维度查询。

### 6.9 前端工程拆分

Vue 前端使用 Vue Router + Pinia。视图组件位于 `src/views`，业务动作位于 `src/composables`，接口封装位于 `src/api`。路由守卫根据登录态和模块权限控制页面访问。Dashboard、风险详情、企业画像和系统日志均使用固定长度分页面板；GIS 使用 3D 立体地图，支持自动旋转、手动拖拽和点位弹窗。

### 6.10 运行治理

Gateway 对每个请求写入 `X-Trace-Id`，日志格式包含 TraceId。所有写接口需要 `X-CSRF-Token`，该 Token 为无 Cookie 的 HMAC 签名 Token；受保护接口需要 `Authorization: Bearer <token>`。响应头包含 CSP、`X-Frame-Options`、`X-Content-Type-Options`、`Referrer-Policy` 和 `Permissions-Policy`。接口文档通过 OpenAPI 暴露，默认地址为 `/swagger-ui.html`。

### 6.11 线程池隔离设计

6 个独立线程池按业务域隔离，避免相互阻塞（详见 `ThreadPoolConfig.java`）：

| 线程池 | 核心 | 最大 | 队列 | 拒绝策略 | 适用场景 |
|---|---|---|---|---|---|
| `semiriskCrawlerPool` | 4 | 8 | 100 | CallerRuns | 公开源爬虫（背压保护） |
| `semiriskAiPool` | 2 | 4 | 50 | CallerRuns | AI 调用（保护 LLM 配额） |
| `semiriskQueryPool` | 8 | 16 | 200 | DiscardOldest | 高频查询（保最新数据） |
| `semiriskReportPool` | 2 | 4 | 20 | Discard | 报告生成（非紧急可丢弃） |
| `semiriskUploadPool` | 2 | 4 | 50 | CallerRuns | 文件上传（背压保护） |
| `semiriskAlertPool` | 2 | 4 | 100 | CallerRuns | 告警处理（背压保护） |

### 6.12 Redis 缓存设计

4 个命名缓存，各自独立 TTL（详见 `RedisCacheConfig.java`）：

| 缓存名 | TTL | 用途 |
|---|---|---|
| `dashboard:overview` | 60s | Dashboard KPI 聚合结果 |
| `enterprise` | 300s | 企业画像搜索结果 |
| `risk:snapshot` | 30s | 风险快照 |
| `knowledge` | 120s | 知识库检索结果 |

使用 `GenericJackson2JsonRedisSerializer` 序列化，Null 值禁止存储。

### 6.13 限流与幂等设计

**滑动窗口限流**（`RateLimitingFilter.java`）：基于 Redis Sorted Set 实现。作用于注册接口（60 秒 2 次）和验证码接口（60 秒 1 次）。Redis 故障时放行（记录警告日志，不阻断请求）。

**请求幂等**（`IdempotencyFilter.java`）：POST/PUT 请求携带 `Idempotency-Key` 请求头，Redis SET NX 5 分钟 TTL。重复提交返回 HTTP 409 Conflict。排除登录、注册、Dashboard、知识库预览接口。

### 6.14 分布式锁设计

`DistributedLockManager.java` 基于 Redisson `RLock`，前缀 `semirisk:lock:`。提供两种模式：
- `executeWithLock(lockName, waitMs, leaseMs, task)` — 可配置等待/租约时间
- `executeWithLockSimple(lockName, task)` — 无限等待

适用于多实例部署下的定时任务串行化（爬虫同步、数据归档）。

### 6.15 安全响应头设计

`TraceIdFilter.java` 为每个响应注入安全头：

| 响应头 | 值 |
|---|---|
| `Content-Security-Policy` | `default-src 'self'`，Tailwind CDN 和 Iconify CDN 白名单 |
| `X-Frame-Options` | `DENY` |
| `X-Content-Type-Options` | `nosniff` |
| `Referrer-Policy` | `no-referrer` |
| `Permissions-Policy` | `camera=(), microphone=(), geolocation=()` |

### 6.16 消息队列设计

`RabbitMqConfig.java` 定义 3 个持久化队列（详见 `RabbitMQ 消息队列`）：

| 队列 | 用途 | DLQ |
|---|---|---|
| `ai.evaluate.queue` | 上传文件 AI 评估 | `ai.evaluate.dlq` |
| `report.generate.queue` | 报告生成任务 | `report.generate.dlq` |
| `crawler.sync.queue` | Gateway ↔ DataService 爬虫同步 | 无 |

消费者 `AiEvaluateConsumer.java` 监听 `ai.evaluate.queue`，反序列化后委托 `UploadAiEvaluateService` 执行结构化 AI 评估。

### 6.17 输入清洗设计

`InputSanitizer.java` 提供统一的输入清洗：
- XSS 标签过滤（`<[^>]*>` 模式）
- 控制字符过滤
- 用户名正则白名单（字母/数字/下划线）
- QQ 邮箱校验
- 角色/状态白名单校验
- 密码强度校验（最少 8 位）
