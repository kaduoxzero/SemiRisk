# SemiRisk — AI 供应链风险智能监测平台（课程设计）

---

## 一、项目概述

SemiRisk 是一门综合性课程设计项目，以半导体产业链为业务背景，设计并实现了一个 AI 驱动的供应链风险监测平台。系统覆盖多源数据采集、风险量化评估、AI 智能推理、实时预警派发、GIS 全球监控、RAG 知识检索和自动化报告生成全链路闭环，采用 Spring Cloud 微服务架构，包含 6 个独立后端服务与 Vue 3 前端，通过 Docker Compose 一键编排部署 7 种中间件与全部应用服务。项目团队共 4 人，本人负责后端架构设计与核心功能开发。

## 三、核心职责

### 1. 设计并实现 6 服务微服务架构，按领域职责拆分业务边界

将单体应用拆分为 Gateway（认证聚合）、Data Service（爬虫采集）、Risk Service（风险测算）、AI Service（大模型推理）、Alert Service（告警流转）、Report Service（报告生成）6 个独立服务，配合 4 个公共模块（common-core/db/middleware/ai）共享基础能力。各服务独立端口、独立 JVM 参数（512m–1024m），通过 OpenFeign 实现服务间 RPC 调用，配置指数退避重试策略（500ms→1s→2s），服务可用性显著提升。

### 2. 构建多层安全防护体系，实现统一 API 网关

基于 Spring Cloud Gateway 实现统一入口，集成 JWT Bearer Token 认证（30 分钟滑动续期）+ HMAC 签名 CSRF Token（无 Cookie 方案）+ Redis 滑动窗口限流（per-endpoint + IP，注册 60s/2 次）+ Sentinel 4 条流控规则与 2 条熔断规则 + POST/PUT 幂等校验（Redis SET NX，5 分钟 TTL）。密码采用 PBKDF2 哈希存储，登录失败 5 次锁定 30 分钟，响应头注入 CSP、X-Frame-Options 等 5 项安全头，构建多层纵深防御。

### 3. 集成 DeepSeek 大模型，实现 AI 驱动的风险推理与结构化输出

通过 Spring AI 对接 DeepSeek API（deepseek-v4-pro），实现风险日报自动生成、知识库 RAG 问答、上传文件 AI 评估等 4 大场景。采用 JSON Schema strict 模式确保 AI 输出结构化可解析，支持 SSE 流式响应实时推送推理过程。设计 Prompt 工程模板，组合本地知识库 + ES multi_match 检索 + 爬虫记录构建上下文，ES 不可用时自动降级本地 RAG 摘要，保障服务连续性。

### 4. 构建 RAG 知识库检索引擎，实现全文检索 + 向量混合搜索

基于 Elasticsearch 8.15 搭建知识库索引（semirisk_knowledge），实现 multi_match 全文检索与 dense_vector 向量检索双通道，通过 RRF（Reciprocal Rank Fusion）算法融合关键词分与向量相似度分。设计批量写入组件（100 条/5 秒自动刷写），ES 故障自动熔断 60 秒、失败文档重新入队，保障数据不丢失。知识库爬虫数据同步后自动建索引，支撑 AI 智能体问答的上下文检索。

### 5. 开发多源 RSS 爬虫系统，实现 9 个国内外数据源自动化采集

设计并实现覆盖中国新闻网（财经/国际/滚动）、SupplyChainDive、FreightWaves、ManufacturingDive、美国联邦公报（出口管制）、WTO 等 9 个 RSS/Atom 数据源的多线程爬虫，支持 12 小时定时调度自动刷新。采用独立线程池（核心 4/最大 8/队列 100/CallerRuns 背压保护），数据经 XSS 过滤、去重、维度分类后写入 MySQL，近三天数据保留、每源最多 12 条，确保数据时效性与系统稳定性。

### 6. 实现异步报告生成系统，支持 PDF/DOCX/PPTX 多格式输出

设计 RabbitMQ 异步报告任务队列（report.generate.queue + DLQ 死信队列），用户选择模板、语言、格式后创建异步任务（PR-时间戳 ID），前端轮询进度，完成后通过 MinIO 下载文件。AI 服务自动生成报告内容，Report Service 异步渲染多格式文件，独立线程池（核心 2/最大 4/队列 20）隔离报告渲染与核心业务，避免阻塞。

### 7. 设计 Docker Compose 全栈编排方案，实现一键部署

编写统一 docker-compose.yml 编排 7 种中间件（MySQL、Redis、ES、MinIO、RabbitMQ、Nacos、Zipkin）+ 应用容器，所有中间件配置 Health Check（TCP/HTTP 探测）与 depends_on condition: service_healthy 启动依赖，确保中间件就绪后应用才启动。应用容器内置 Nginx 反向代理（前端静态资源 + API 转发），supervisord 管理 6 个 Java 进程，支持 `docker compose up -d` 一键启动全栈。

### 8. 实现分布式链路追踪与 6 线程池隔离治理

集成 Zipkin 实现跨服务调用链路可视化追踪，Gateway 为每个请求写入 X-Trace-Id 并传播至下游。设计 6 个业务隔离线程池（爬虫/AI/查询/报告/上传/告警），差异化配置核心线程数、队列容量与拒绝策略：查询池 DiscardOldest 保最新数据，报告池 Discard 非紧急可弃，爬虫/上传/告警池 CallerRuns 背压保护，有效防止线程资源竞争导致的服务雪崩。

## 四、项目亮点

1. **AI 原生架构**：深度集成 LLM 大模型，覆盖风险推理、RAG 知识问答、结构化输出、流式响应等 4 大 AI 场景，将 AI 能力融入业务全链路而非简单 API 调用。
2. **多层安全体系**：JWT + HMAC CSRF + Sentinel 限流 + 幂等校验 + PBKDF2 + 安全响应头 + 输入清洗 + 登录防爆锁，8 层安全防护覆盖认证、传输、存储、输入全链路。
3. **高可用容错设计**：Redis Cluster 集群、Feign 降级 + 指数退避重试、ES 故障自动熔断降级、RabbitMQ DLQ 死信队列、分布式锁串行化定时任务，多级容错保障系统稳定运行。
4. **全栈容器化部署**：Docker Compose 一键编排 13 个容器（7 中间件 + 6 应用服务），Health Check + 启动依赖 + 自动重启，实现从零到可用的一键部署。
5. **精细化资源治理**：6 个业务隔离线程池 + 4 个独立 TTL Redis 缓存 + 3 个 RabbitMQ 持久化队列，按业务域差异化配置资源策略，避免相互阻塞与资源争抢。
